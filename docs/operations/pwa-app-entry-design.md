# 홈 화면 아이콘 = 회원 앱 — PWA 진입 흐름 설계

작성일: 2026-07-27

## 배경

원생·학부모는 관리 콘솔(마이페이지)을 **앱처럼** 쓰고 싶어 한다. 콘솔은 모바일에서
하단 탭바 등 웹앱 형태로 이미 다듬어져 있지만, 홈 화면에 추가한 아이콘을 누르면
콘솔이 아니라 **공개 메인 사이트**가 열린다. 로그인하거나 콘솔로 이동하는 조작을
한 번 더 해야 대시보드에 닿기 때문에 "앱을 쓰는 감각"이 진입 순간에 끊긴다.

목표: **아이콘 → 대시보드**. 세션이 풀렸으면 **아이콘 → 로그인 → 대시보드**.
단, 앱 안에서 공개 사이트로도 쉽게 갈 수 있어야 한다(일반 방문객, 그리고 사이트를
둘러보고 싶은 회원).

## 현재 구조와 실패 원인

커밋 `07b9512`에서 매니페스트를 둘로 나눠 대응했다.

- `public/manifest.webmanifest` — `start_url: "/"`, 루트 레이아웃이 링크
- `public/manifest-admin.webmanifest` — `start_url: "/admin"`, `app/admin/layout.tsx`가
  `metadata.manifest`로 오버라이드

이 방식은 **문서를 처음 연 주소**에 결과가 좌우된다. Safari는 페이지 로드 시점의
`<link rel="manifest">`를 잡는데, 회원의 실제 동선은

```
/login (문서 로드 — 공개 매니페스트) → 로그인 → 클라이언트 내비게이션으로 /admin
```

이다. `/admin`은 소프트 내비게이션으로 도달하므로 문서 로드는 일어나지 않고,
브라우저가 붙잡고 있는 매니페스트는 여전히 공개용(`start_url: "/"`)이다. 그래서
대시보드 화면에서 공유 → 홈 화면에 추가를 해도 **메인 사이트가 등록**된다.

즉 이건 값을 잘못 넣은 버그가 아니라 **"페이지별 매니페스트"라는 접근 자체가
SPA 내비게이션과 맞지 않는 문제**다. 링크 태그를 더 정확히 갱신하는 식으로
보강해도 "어느 페이지에서 문서를 열었는가"에 계속 의존한다.

## 설계

### 1. 매니페스트를 사이트 전체 1개로 통합

`manifest-admin.webmanifest`를 삭제하고 `app/admin/layout.tsx`의 `metadata.manifest`
오버라이드를 제거한다. 사이트 전체가 `manifest.webmanifest` 하나를 쓴다.

| 필드 | 값 | 근거 |
|---|---|---|
| `id` | `"/"` (유지) | 안드로이드의 기존 설치를 '새 앱'이 아니라 '업데이트'로 인식시킨다 |
| `start_url` | `"/app"` | 아래 2절 |
| `scope` | `"/"` | 공개 사이트도 앱 **안에서** 열려 앱 이탈이 없다 |
| `display` | `"standalone"` (유지) | |
| `name` / `short_name` | `KTDOC 춤누리` / `KTDOC` (유지) | 회원·방문자 모두에게 자연스러운 이름 |
| `background_color` / `theme_color` | `#f6f1e6` | 앱의 착지면은 콘솔이고 콘솔 기본값은 라이트(한지). 실행 중 상태바 색은 5절의 `<meta name="theme-color">`가 덮는다 |
| `icons` | SVG + 192/512 PNG + maskable 512 | 4절 |

어느 페이지에서 추가하든 결과가 같아진다. "문서를 처음 연 주소"에 좌우되던
취약점이 원인째 사라진다.

트레이드오프: 공개 사이트를 **별도 앱으로** 설치하는 개념은 없어진다. 방문자가
메인에서 홈 화면에 추가하면 로그인 화면이 뜬다. PWA는 처음부터 회원 앱으로
도입됐고(커밋 `8f01749` "설치 가능 + 멤버 앱화"), 공개 사이트를 설치하는 수요는
사실상 없다고 판단해 수용한다. 대신 3절에서 앱 안에서 사이트로 가는 길을 보장한다.

### 2. `/app` — 앱 진입점 (UI 없는 서버 리다이렉트)

```
세션 없음          → /login?callbackUrl=/admin   (로그인 후 대시보드로 복귀)
세션 있음 · pending → /                          (승인 대기 — 공개 홈)
세션 있음 · active  → /admin                     (대시보드)
```

- 서버 컴포넌트, `dynamic = 'force-dynamic'`, `robots: noindex`
- 임시 비밀번호 강제 변경은 기존 미들웨어가 먼저 가로챈다(변경 없음)
- 미들웨어 matcher에 걸리지만 보호 경로가 아니므로 그대로 통과한다

**`/admin`을 직접 `start_url`로 쓰지 않는 이유**: iOS는 홈 화면에 추가하는 순간
`start_url`이 아이콘에 **각인**된다. 나중에 착지 지점을 바꾸고 싶어지면(역할별 착지,
승인 대기 안내 등) 매니페스트 수정만으로는 이미 설치된 아이콘을 못 바꾸고 전 회원이
재설치해야 한다. **절대 바뀌지 않는 진입 URL 하나**를 두고 분기는 서버에서 한다.

### 3. 앱 안에서 공개 사이트로 가는 길

`scope: "/"`이므로 공개 사이트는 앱 창 안에서 열린다. 다만 현재 '사이트 보기' 링크가
`target="_blank"`라 **standalone에서는 Safari로 튕겨나간다** — 앱 감각이 끊기는
가장 큰 구멍이다.

- `lib/pwa/useStandalone.ts` — standalone 여부를 하이드레이션 안전하게 구독하는 훅
  (`useSyncExternalStore`, SSR 스냅샷 `false`). `AddToHomeCard`의 기존 판별 로직도
  이 훅으로 통일한다.
- `AdminShell`(사이드바 하단)과 `AdminMoreSheet`(모바일 더보기 시트)의 '사이트 보기'는
  standalone일 때 `target`을 붙이지 않고 같은 창에서 연다. `↗` 표시도 그때는 뺀다.
- 돌아오는 길은 이미 있다 — 공개 헤더가 로그인 상태에서 대시보드 버튼을 노출한다.
- 로그아웃 상태로 앱을 열어 로그인 화면이 떴을 때도 나갈 수 있게, 로그인 화면에
  '사이트 둘러보기' 링크를 명시한다(지금은 로고만 링크라 눈에 띄지 않는다).

### 4. 아이콘

매니페스트 아이콘이 `/icon.svg` 하나뿐이다. 안드로이드는 마스커블 아이콘이 없으면
홈 화면에서 흰 원 안에 축소해 박아 넣어 앱처럼 보이지 않는다. 또 이 SVG는 `춤` 글자를
`font-family: 'Noto Serif KR'`로 그리므로 폰트가 없는 환경에서 대체 글꼴로 렌더된다.

`scripts/`에 sharp 기반 생성 스크립트를 두고 결과 PNG를 저장소에 커밋한다.

- `public/icon-192.png`, `public/icon-512.png` — `purpose: "any"`
- `public/icon-maskable-512.png` — `purpose: "maskable"`, 로고를 안전영역(약 80%) 안에 배치
- 생성 후 **눈으로 확인**한다. `춤` 글자가 대체 글꼴로 깨져 나오면 기존
  `app/apple-icon.png`(180px, 이미 올바르게 렌더된 결과물)를 소스로 삼는다.

### 5. iOS 상태바

현재 `appleWebApp.statusBarStyle: 'black-translucent'` — 콘텐츠가 상태바 아래까지
올라가고 상태바 글자는 **항상 흰색**이다. 콘솔 기본값이 라이트(아이보리 상단바,
`--bg-rgb: 246, 241, 230`)라 시간·배터리가 사실상 보이지 않는다.

- `statusBarStyle`을 `'default'`로 바꾼다(상태바 글자 어두움, 콘텐츠는 상태바 아래에서 시작).
- `<meta name="theme-color">`를 테마에 따라 갱신한다 — 콘솔 라이트 `#f6f1e6`,
  콘솔 다크·공개 사이트 `#0a0a0a`. `AdminThemeContext`가 `data-admin-theme`를
  붙이고 떼는 지점에서 함께 처리한다.

레이아웃 영향: standalone에서 `env(safe-area-inset-top)`가 0이 되어 콘솔 상단바와
공개 헤더가 그만큼 짧아진다. 헤더는 `ResizeObserver` 실측 기반(`--header-offset`)이라
자동으로 적응하고, `.admin-topbar`도 `calc(56px + env(...))` 형태라 안전하다.

**위험과 폴백**: iOS의 상태바 글자색은 `statusBarStyle`로 고정되고 실행 중 바꿀 수
없다. `default`는 콘솔 라이트(기본값)에 맞춘 선택이므로, 콘솔을 다크로 바꾼 회원은
어두운 배경 위 어두운 글자를 보게 될 수 있다. 배포 후 실기기에서 다음을 확인하고
결과에 따라 택한다.

1. 라이트 콘솔에서 시간·배터리가 잘 보이는가 → 목표 달성
2. 다크 콘솔에서도 읽히는가 → 그대로 확정
3. 다크 콘솔에서 안 읽히면 → `theme-color`를 아이보리로 고정해 상태바 띠만 밝게 유지
   (다크 콘솔에서 상단에 밝은 띠가 보이지만 가독성은 확보된다)

### 6. 재설치 안내

iOS는 기존 아이콘에 **옛 주소가 이미 각인**돼 있어 배포만으로는 고쳐지지 않는다.
이미 추가한 회원은 한 번 지우고 다시 추가해야 한다.

- `AddToHomeCard`의 '나중에' 저장 키를 `a2hs-dismissed` → `a2hs-dismissed-v2`로 올려
  이전에 닫았던 회원에게도 카드를 다시 노출한다.
- 카드에 "이미 추가하셨다면 한 번 지우고 다시 추가해 주세요" 한 줄을 넣는다
  (i18n 키 추가, ko/en 양쪽).

## 범위 밖

- 오프라인 폴백 페이지 — 현재 서비스워커는 캐시 폴백만 한다. 별도 과제.
- 공개 사이트를 별도 앱으로 설치 — 1절에서 명시적으로 포기했다.
- 안드로이드 설치 프롬프트 UX 변경 — 기존 `beforeinstallprompt` 흐름 유지.

## 검증

로컬:

- `/app` 리다이렉트 3케이스(비로그인 / pending / active)를 실제 계정으로 확인
- 공개 페이지·로그인 화면·콘솔 어디서 문서를 로드해도 `link[rel=manifest]`가
  `/manifest.webmanifest` 하나로 동일한지
- 콘솔 라이트/다크 두 테마에서 상단바·하단 탭바 대비 확인(프로젝트 기본 루틴)

실기기(배포 후):

- 아이폰에서 기존 아이콘 삭제 → 재추가 → 아이콘 탭 → **대시보드**
- 로그아웃 후 아이콘 탭 → 로그인 화면 → 로그인 → **대시보드**
- 앱 안에서 '사이트 보기' → Safari로 튕기지 않고 앱 안에서 열리는지, 헤더의
  대시보드 버튼으로 돌아오는지
- 상태바 가독성(5절 1~3)
- 안드로이드에서 설치 → 아이콘 모양(마스커블) → 아이콘 탭 → 대시보드
