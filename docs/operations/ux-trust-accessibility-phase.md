# KTDOC 신뢰·접근성 개선 Phase

> 작성일: 2026-07-09
> 배경: "홍보 사이트 + 원생·학부모 내부 도구"라는 이중 목적에 대해, 비판적인 일반 방문자와
> 디지털 사용이 서툰 사용자(고령 학부모 등) 관점의 UX 감사 결과를 실행 로드맵으로 정리
> 상태: **진행 중** — 아래 §4 순서대로 해결하며 §5에 진행 기록을 남긴다

## 1. 배경과 목적

이 사이트의 사용자에는 두 그룹이 있다.

1. **비판적인 일반 방문자** — 학원을 알아보는 예비 학부모. 사이트의 완성도·신뢰 신호
   (연락처, 방침, 콘텐츠 관리 상태)를 근거로 등록 여부를 판단한다.
2. **디지털 사용이 서툰 내부 사용자** — 원생과 학부모, 특히 고령·비영어권 학부모.
   실제 소통 도구는 카카오톡·문자·전화이며, 이메일·앱 설치·구독 설정은 장벽이다.

감사에서 드러난 문제의 공통 패턴은 두 가지다.

- **막혔을 때 사람에게 닿는 길이 없다** — 비밀번호 분실, 승인 대기, 문의, 신청 유실
  등 어떤 실패 지점에서도 "다음에 할 일"이 안내되지 않는다.
- **전달 수단이 대상층의 도구가 아니다** — 웹 푸시(설치 필요)·.ics 구독·이메일 등
  개발자의 도구로 설계되어 있고, 카톡·문자·전화·종이 같은 로우테크 대안이 없다.

## 3. 보류 항목 (서비스 오픈 시 확정)

- **이메일 서비스 복구/교체** (#1) — 발송 인프라(Gmail 재설정 vs Resend 등 전환)는
  서비스 오픈 시점에 확정하기로 결정(2026-07-09). 이에 따라 §4의 각 항목은
  **이메일 없이 성립하는 1차 해법**을 우선하고, 이메일 의존 부분(셀프서비스 재설정
  링크, 가입·승인 메일 통보)은 오픈 시 2차로 붙인다.
- **문자/카카오 알림톡 발송** — 유료 외부 서비스라 오픈 시 함께 검토.

## 4. 실행 순서

각 항목은 **목표**와 **완료 기준(DoD)** 을 갖는다. 위에서 아래로 순서대로 진행한다.

### Step 1. 비밀번호 재설정 — 운영진 발급형 ✅ 완료 (2026-07-09)
- [x] 목표: 비밀번호를 잊은 회원이 "선생님에게 요청 → 임시 비밀번호 발급"으로 복구
- 구현: 회원 관리(`/admin/members`)에 **임시 비밀번호** 버튼(운영진, 관리자 대상 발급은
  관리자만). 숫자 8자리 발급(전화 전달 용이) → 모달에 1회 표시. 임시 비밀번호로
  로그인하면 미들웨어가 `/account/password`(새 비밀번호 설정)로 강제 이동, 설정
  완료 시 새 비밀번호로 자동 재로그인해 역할별 첫 화면으로. 로그인 화면에
  분실 안내 + 전화 연결(SEO 패널 연락처 단일 소스) 추가. MySQL 0030 적용.
- DoD 충족: 발급→임시 로그인→강제 변경→착지 전 과정 E2E 검증 완료.
  셀프서비스(이메일 링크) 재설정은 이메일 확정 후 2차(§3).

### Step 2. 개인정보처리방침·이용약관 ✅ 완료 (2026-07-09)
- [x] 목표: 법적 고지 페이지 신설 + 수집·이용 동의 근거 마련
- 구현: `/privacy`·`/terms` 페이지(이중 언어, 문안은 `lib/legalContent.ts`에서 코드
  버전 관리) + 푸터 법적 링크 + 가입 폼 동의 체크박스(서버 검증 포함, 미동의 400).
  동의 시각은 `users.terms_agreed_at`(MySQL 0031)에 기록. 아동(COPPA) 조항과
  사진 공개 opt-in 동의의 문서 근거 포함. 문의처는 SEO 패널 연락처 단일 소스.
  준거법은 소재지(뉴저지) 기준.
- DoD 충족: 페이지·푸터·가입 동의 모두 동작 확인.
  ⚠️ **문안은 초안 상태 — 오픈 전 원장·법률 검토로 확정 필요.**

### Step 3. 승인 플로우 통보 ✅ 완료 (2026-07-10)
- [x] 목표: 가입~승인 사이의 깜깜이 제거 (이메일 없이 성립하는 범위)
- 구현: 시스템 알림 헬퍼(`lib/push/system.ts`, 기존 알림함+웹 푸시 재사용, 실패해도
  본 흐름을 막지 않음) — ① 신규 가입 → 운영진(선생님·관리자) 인앱+푸시
  ② 승인 → 가입자 인앱 알림("가입이 승인되었습니다", 다음 로그인 시 확인)
  ③ pending 로그인 → 이동 대신 대기 안내 패널(예상 소요·전화 연결), 가입 완료
  화면도 동일 안내 + "이메일로 안내" 오문구 제거(알림 안내로 교체)
- DoD 충족: 가입→운영진 알림함(수신 3명)→대기 로그인 안내→승인→가입자
  알림함 확인까지 전 과정 E2E 검증.

### Step 4. 문의 동선 (사람에게 닿는 길)
- [ ] 목표: 어디서 막히든 한 번의 탭으로 사람에게 연결
- 방식: 푸터·Q&A·로그인/가입 오류·승인 대기 화면에 전화(tel:)·카카오톡 채널 버튼 노출.
  연락처 원본은 기존 SEO 패널(D1 `seo.business`) 단일 소스 재사용.
  카카오 채널 개설 여부는 원장 확인 필요.
- DoD: 신규 방문자·막힌 회원 모두 2탭 이내에 전화/카톡 도달.

### Step 5. 멤버 콘솔 가독성 (시니어 모드)
- [ ] 목표: 매주 쓰는 내부 도구를 노안 기준으로 읽을 수 있게
- 방식: 멤버 화면(원생·학부모용 `/admin` 뷰) 본문 최소 16px·대비 상향,
  글자 크기 토글(보통/크게) 검토. 홍보용 공개 페이지의 다크 아이덴티티는 유지.
- DoD: 멤버 핵심 화면(홈·캘린더·내 수업·알림)이 WCAG AA 대비 + 16px 이상.

### Step 6. 로그인 후 동선·명칭 정리
- [ ] 목표: "관리"라는 문턱 제거, 첫 화면에서 할 일이 보이게
- 방식: 멤버 진입 라벨·랜딩 개선(예: "내 공간"), 역할별 첫 화면에 이번 주 일정·새 알림
  요약, KO/EN 토글 시인성 개선.
- DoD: 로그인 직후 화면만 보고 "오늘 뭘 확인해야 하는지" 알 수 있음.

### Step 7. 알림 도달 보강 (푸시 의존 완화)
- [ ] 목표: 푸시 미설치 사용자에게도 공지가 닿는 구조
- 방식: 그림 단계별 푸시 설치 가이드(아이폰/안드로이드 분리), 헤더 알림 뱃지,
  중요 공지의 홈 화면 배너 노출. 문자/알림톡은 보류 항목(§3)과 연동.
- DoD: 푸시 없이 접속만 해도 새 공지를 놓치지 않음 + 설치 가이드 완주율 개선.

### Step 8. 일정의 로우테크 대안
- [ ] 목표: .ics 구독을 못 해도 일정을 가져갈 수 있게
- 방식: 월간 일정 인쇄/이미지 저장 뷰(카톡으로 전달 가능한 한 장짜리).
- DoD: 캘린더 페이지에서 "이번 달 일정 이미지 저장" 1탭 제공.

### Step 9. 마감 이슈 일괄 정리
- [ ] 한글 slug 이벤트 메타데이터 버그 수정 (카톡 공유 미리보기)
- [ ] 학부모-자녀 매칭 보조(운영진 매칭 화면에 후보 추천)
- [ ] FAQ 초기 콘텐츠 등록(원장 확인 항목과 연결)
