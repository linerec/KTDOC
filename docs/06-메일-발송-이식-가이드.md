# 메일 발송 연동 이식 가이드 (Resend + SMTP)

이 프로젝트의 문의 알림 메일 구조를 **다른 프로젝트에 그대로 옮겨 심기 위한** 문서다.
디자인(설정 화면의 생김새)은 프로젝트마다 다르게 하되, 아래 네 가지는 동일하게
가져가는 것을 전제로 한다:

1. **발송 방식 이중화** — Resend(HTTP API)와 SMTP 중 운영자가 고른다
2. **공용 발송 모듈** — `resolveMailConfig()` + `sendMail()` 두 함수가 전부다
3. **환경설정 저장** — 키·SMTP 정보는 관리자 화면에서 저장하고, 시크릿은 절대
   응답에 담지 않는다
4. **환경변수 폴백** — 설정 화면을 한 번도 열지 않은 배포도 환경변수만으로 동작한다

원본 구현: `lib/mail/notify.ts`, `lib/store/settings.ts`,
`app/api/settings/route.ts`, `app/api/settings/mail-test/route.ts`.

---

## 0. 전체 그림

```
[관리자 설정 화면] ──PUT /api/settings──▶ [설정 저장소(DB/파일)]
                                              │
[문의 접수 등 호출부] ──▶ resolveMailConfig(settings ⊕ 환경변수)
                                              │
                                              ▼
                                   ResolvedMailConfig
                                   ├─ 'resend' → fetch api.resend.com
                                   ├─ 'smtp'   → nodemailer │ worker-mailer
                                   └─ 'none'   → 발송 건너뜀 (사유 로그)
```

핵심 설계 원칙 — 이식할 때 이것만은 지킬 것:

- **`sendMail()` 은 절대 던지지 않는다.** `{ ok, detail }` 을 돌려준다.
  메일이 치명적인지 아닌지는 호출부가 정한다. (이 프로젝트에서는 "DB 저장이
  성공이면 접수 완료, 메일 실패는 플래그만 남김" — 메일에만 의존하면 스팸 분류
  한 번에 문의가 사라진다.)
- **시크릿(API 키·SMTP 비밀번호)은 API 응답에 절대 담지 않는다.**
  `resendApiKeySet` / `passwordSet` 같은 불리언만 내려간다.
- **PUT 에서 빈 시크릿 = 기존 값 유지.** 화면은 저장된 시크릿을 받지 못하므로,
  매번 재입력을 요구하면 다른 칸을 고칠 때마다 키가 지워진다.
- **`provider: ''`(미설정) = 환경변수 폴백.** 기존에 `RESEND_API_KEY` 환경변수로
  보내던 배포가 설정 화면을 열지 않아도 그대로 돈다.
- **테스트 발송은 저장본을 대상으로 한다.** 화면의 미저장 값을 받으면 "빈 값 =
  유지" 규칙과 얽혀서, 테스트는 되는데 저장본은 다른 상태가 될 수 있다.

## 1. 설정 스키마

설정 저장소가 무엇이든(D1, Postgres, 파일…) **스키마와 기본값 병합**은 동일하다.
저장은 JSON 한 덩어리(`key = 'site'` 한 행)로 충분하다.

```ts
export interface SmtpSettings {
  host: string
  /** Cloudflare Workers 는 25 포트로 나갈 수 없다 — 465(TLS)/587(STARTTLS)만 의미가 있다. */
  port: number
  /** true = 접속부터 TLS(465). false = 평문 접속 후 STARTTLS 승급(587). */
  secure: boolean
  username: string
  password: string
}

export interface MailSettings {
  /** '' = 미설정(환경변수 폴백) */
  provider: '' | 'resend' | 'smtp'
  /** 알림이 도착할 주소. 비우면 코드 기본값(예: 사이트 대표 메일). */
  to: string
  /** 발신 주소. 비우면 환경변수(예: MAIL_FROM). 도메인 인증된 주소여야 한다. */
  from: string
  resendApiKey: string
  smtp: SmtpSettings
}

export const DEFAULT_MAIL: MailSettings = {
  provider: '',
  to: '',
  from: '',
  resendApiKey: '',
  smtp: { host: '', port: 465, secure: true, username: '', password: '' },
}
```

읽을 때는 항상 기본값과 **깊은 병합**을 한다 — 나중에 필드를 추가해도 옛 저장본이
깨지지 않는다:

```ts
function withDefaults(partial: Partial<{ mail: Partial<MailSettings> }> | null) {
  return {
    mail: {
      ...DEFAULT_MAIL,
      ...(partial?.mail ?? {}),
      smtp: { ...DEFAULT_MAIL.smtp, ...(partial?.mail?.smtp ?? {}) },
    },
  }
}
```

> 이 프로젝트는 D1 `settings` 표 + 로컬 개발용 `.data/settings.json` 파일 폴백을
> 쓴다(`lib/store/settings.ts` 의 `readSettings`/`writeSettings`). 저장소가 이미
> 있는 프로젝트라면 그 위에 `mail` 키만 얹으면 된다.

## 2. 공용 발송 모듈

`lib/mail/mailer.ts` 로 통째로 복사해 쓸 수 있는 범용 버전. 프로젝트 고유값은
상수 두 개(`SENDER_NAME`, `FALLBACK_TO`)와 환경변수 이름뿐이다.

```ts
import 'server-only'

// ── 프로젝트에 맞게 바꿀 값 ─────────────────────────────
const SENDER_NAME = '사이트 이름'        // 발신자 표시 이름
const FALLBACK_TO = 'owner@example.com'  // 수신처 미설정 시 기본값
// 환경변수: RESEND_API_KEY (Resend 폴백 키), MAIL_FROM (발신 주소 폴백)
// ────────────────────────────────────────────────────────

export interface MailMessage {
  subject: string
  text: string
  /** 답장 버튼이 문의자에게 향하도록. 없으면 생략된다. */
  replyTo?: string
}

export type ResolvedMailConfig =
  | { provider: 'resend'; apiKey: string; to: string; from: string }
  | { provider: 'smtp'; smtp: SmtpSettings; to: string; from: string }
  | { provider: 'none'; reason: string }

/**
 * 설정과 환경변수를 합쳐 "실제로 발송에 쓸 값"을 정한다.
 * 운영자가 고른 값이 우선, provider 가 '' 이면 환경변수 폴백.
 */
export function resolveMailConfig(mail: MailSettings): ResolvedMailConfig {
  const to = mail.to.trim() || FALLBACK_TO
  const from = mail.from.trim() || process.env.MAIL_FROM || ''

  if (mail.provider === 'smtp') {
    if (!mail.smtp.host.trim()) return { provider: 'none', reason: 'smtp-no-host' }
    if (!from) return { provider: 'none', reason: 'no-from' }
    return { provider: 'smtp', smtp: mail.smtp, to, from }
  }

  // '' (미설정) 과 'resend' 는 같은 경로 — 설정에 키가 없으면 환경변수 키
  const apiKey = mail.resendApiKey.trim() || process.env.RESEND_API_KEY || ''
  if (!apiKey) return { provider: 'none', reason: 'no-api-key' }
  if (!from) return { provider: 'none', reason: 'no-from' }
  return { provider: 'resend', apiKey, to, from }
}

/** Resend 는 SDK 가 필요 없다 — HTTP API 한 번이면 된다. */
async function sendViaResend(
  apiKey: string, to: string, from: string, message: MailMessage,
): Promise<void> {
  const res = await fetch('https://api.resend.com/emails', {
    method: 'POST',
    headers: { Authorization: `Bearer ${apiKey}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({
      from: `${SENDER_NAME} <${from}>`,
      to: [to],
      reply_to: message.replyTo || undefined,
      subject: message.subject,
      text: message.text,
    }),
  })
  if (!res.ok) throw new Error(`resend responded ${res.status}: ${await res.text()}`)
}

async function sendViaSmtp(
  smtp: SmtpSettings, to: string, from: string, message: MailMessage,
): Promise<void> {
  const { default: nodemailer } = await import('nodemailer')
  const transport = nodemailer.createTransport({
    host: smtp.host,
    port: smtp.port,
    secure: smtp.secure,
    // 자격증명을 보낼 때는 STARTTLS 강제 — 평문으로 비밀번호를 흘리지 않는다
    requireTLS: !smtp.secure && Boolean(smtp.username),
    auth: smtp.username ? { user: smtp.username, pass: smtp.password } : undefined,
    // 접수 응답이 메일 서버 장애에 몇 분씩 끌려가면 안 된다
    connectionTimeout: 10_000,
    greetingTimeout: 10_000,
    socketTimeout: 20_000,
  })
  await transport.sendMail({
    from: { name: SENDER_NAME, address: from },
    to,
    replyTo: message.replyTo,
    subject: message.subject,
    text: message.text,
  })
}

/**
 * 해석된 설정으로 메일 한 통을 보낸다.
 * 실패해도 던지지 않는다 — 치명 여부는 호출부가 정한다.
 * detail 은 테스트 발송 화면이 원인을 보여줄 때 쓴다.
 */
export async function sendMail(
  config: ResolvedMailConfig, message: MailMessage,
): Promise<{ ok: boolean; detail?: string }> {
  if (config.provider === 'none') {
    console.warn(`[mail] not configured (${config.reason}); notification skipped`)
    return { ok: false, detail: config.reason }
  }
  try {
    if (config.provider === 'smtp') {
      await sendViaSmtp(config.smtp, config.to, config.from, message)
    } else {
      await sendViaResend(config.apiKey, config.to, config.from, message)
    }
    return { ok: true }
  } catch (error) {
    console.error(`[mail] ${config.provider} send failed`, error)
    return { ok: false, detail: error instanceof Error ? error.message : String(error) }
  }
}
```

호출부는 이런 모양이 된다:

```ts
const config = resolveMailConfig((await readSettings()).mail)
const result = await sendMail(config, {
  subject: `[홈페이지 문의] ${name}`,
  text: body,
  replyTo: customerEmail || undefined,
})
// result.ok 가 false 여도 요청 자체를 실패로 만들지 말 것 —
// "저장이 성공이면 접수 완료"가 이 구조의 존재 이유다.
```

## 3. 런타임 갈래 — 배포 대상이 어디인가

위 모듈은 **Node 런타임 전용**이다(nodemailer). 배포 대상에 따라 갈린다:

### 3a. Vercel / 일반 Node 서버 → 그대로 끝

nodemailer 하나면 된다. 이 절의 나머지는 무시해도 된다.
`next.config.ts` 에 `serverExternalPackages: ['nodemailer']` 만 추가한다.

### 3b. Cloudflare Workers (OpenNext) → SMTP 는 worker-mailer 벤더 사본

**workerd 에서는 nodemailer 가 동작하지 않는다** (Node 소켓이 없다). Resend 만
쓸 거라면 문제없지만, SMTP 를 지원하려면 `cloudflare:sockets` 기반
worker-mailer 가 필요하고, 이건 npm 패키지를 그대로 못 쓴다:

1. 원본의 `import { connect } from 'cloudflare:sockets'` (정적 import)는
   OpenNext 의 esbuild 번들 단계가 해석하지 못해 배포 빌드가 죽는다
2. 앱 코드(lib/) 안에 넣으면 Turbopack 이 동적 import 를 던지는 스텁으로
   바꿔버린다 (실측)

그래서 **3중 장치**가 필요하다 (전부 이 저장소에서 복사하면 된다):

| 조각 | 이 저장소의 위치 | 역할 |
|---|---|---|
| 벤더 사본 | `vendor/worker-mailer-cf/` | `cloudflare:sockets` 를 지연 로드로 패치한 worker-mailer. 패치 내용과 갱신 절차는 `index.mjs` 머리말에 있다 |
| 사본 강제 스크립트 | `scripts/vendor-install.mjs` + package.json `postinstall` | npm 은 `file:` 의존성을 심링크로 깔고, Next 는 심링크 패키지의 `serverExternalPackages` 를 무시한다 — 실디렉터리 사본으로 바꿔치기한다 |
| 번들 제외 | `next.config.ts` `serverExternalPackages: ['worker-mailer-cf', 'nodemailer']` | 두 라이브러리 모두 Turbopack 이 건드리지 못하게 한다 |

package.json 에는:

```jsonc
{
  "scripts": { "postinstall": "node scripts/vendor-install.mjs" },
  "dependencies": {
    "nodemailer": "^9.0.5",
    "worker-mailer-cf": "file:vendor/worker-mailer-cf"
  }
}
```

그리고 `sendViaSmtp` 앞에 런타임 분기를 넣는다 (`lib/mail/notify.ts` 원문 참조):

```ts
function onWorkers(): boolean {
  return typeof navigator !== 'undefined' && navigator.userAgent?.includes('Cloudflare-Workers')
}

// sendViaSmtp 안에서:
if (onWorkers()) {
  const { WorkerMailer } = await import('worker-mailer-cf')
  await WorkerMailer.send(
    {
      host: smtp.host, port: smtp.port,
      secure: smtp.secure, startTls: !smtp.secure,
      credentials: smtp.username
        ? { username: smtp.username, password: smtp.password }
        : undefined,
      authType: ['plain', 'login'],
      socketTimeoutMs: 20_000, responseTimeoutMs: 15_000,
    },
    {
      from: { name: SENDER_NAME, email: from },
      to, reply: message.replyTo,
      subject: message.subject, text: message.text,
    },
  )
  return
}
// …이하 nodemailer 경로
```

두 라이브러리 모두 **지연 import** 라서 반대쪽 런타임에서는 평가되지 않는다 —
이 구조를 유지해야 한다. 최상단 정적 import 로 바꾸는 순간 한쪽 빌드가 깨진다.

## 4. 설정 API — 시크릿 취급 규칙

### GET — 공개 뷰만 내려준다

시크릿 원문 대신 "저장돼 있는지" 불리언만. 화면은 그걸로
"저장됨 — 변경할 때만 입력" 같은 자리표시를 만든다.

```ts
function publicView(mail: MailSettings) {
  const { resendApiKey, smtp, ...rest } = mail
  return {
    ...rest,                                    // provider, to, from
    resendApiKeySet: Boolean(resendApiKey),
    smtp: { ...smtp, password: '', passwordSet: Boolean(smtp.password) },
  }
}
```

### PUT — 부분 업데이트 + 빈 시크릿 = 유지

- **보낸 키만 반영한다.** 요청 본문에 없는 필드는 건드리지 않는다 — 설정 화면이
  탭별 저장이어도 다른 탭 값이 지워지지 않는다.
- 이메일 주소(`to`/`from`)는 형식 검증 후 틀리면 **400 으로 거절**한다. 조용히
  버리면 운영자는 저장됐다고 믿는다. (주소가 틀리면 문의가 어디에도 안 간다.)
- 포트는 1~65535 정수 검증.
- 시크릿 두 개(`resendApiKey`, `smtp.password`)는 **비어 있지 않을 때만** 덮어쓴다:

```ts
if (typeof body.mail.resendApiKey === 'string' && body.mail.resendApiKey.trim()) {
  settings.mail.resendApiKey = body.mail.resendApiKey.trim().slice(0, 200)
}
if (typeof body.mail.smtp?.password === 'string' && body.mail.smtp.password) {
  settings.mail.smtp.password = body.mail.smtp.password.slice(0, 200)
}
```

> 이 규칙의 대가: 시크릿을 **지우는** 경로가 없다. 필요하면 명시적인 "키 삭제"
> 액션을 따로 만들 것 — "빈 값으로 저장 = 삭제"로 바꾸면 안 된다.

전체 검증 흐름은 `app/api/settings/route.ts` 의 `if (body.mail) { … }` 블록을
그대로 옮기면 된다.

### 테스트 발송 라우트 — 반드시 같이 이식할 것

메일 설정은 **조용히 실패하는 자리**다. 틀린 SMTP 비밀번호는 실제 문의가 유실될
때에야 드러난다. 저장 직후 눌러볼 수 있는 확인 경로가 없으면 이 구조는 미완성이다.

`app/api/settings/mail-test/route.ts` 를 옮긴다. 요점:

- **세션 필수** + **rate limit** (이 프로젝트는 IP 당 5회/10분) — 오타 난 설정으로
  연타하면 상대 SMTP 서버가 이쪽을 차단할 수 있다
- **저장본으로 발송한다** (`resolveMailConfig(await readSettings())`) — 화면의
  미저장 값을 받지 않는다
- 미설정이면 400 + `config.reason`, 실패면 502 + `result.detail` — 화면이 원인을
  보여줄 수 있게 한다
- 본문에 발송 방식·수신 주소·발신 주소를 적는다 — 도착한 메일만 보고도 어느
  설정이 동작했는지 알 수 있다

## 5. 설정 화면 체크리스트 (디자인 자유)

생김새는 프로젝트마다 다르게 하되, 동작은 이것을 갖춘다:

- [ ] 발송 방식 선택: 미설정(환경변수) / Resend / SMTP — SMTP 선택 시에만
      host·port·secure·username·password 칸 노출
- [ ] 시크릿 입력칸: `…Set` 플래그가 true 면 placeholder 로 "저장됨 — 변경할
      때만 입력" 표시, 값은 항상 빈 칸으로 시작
- [ ] 포트 프리셋 안내: 465 = TLS(secure ✓), 587 = STARTTLS(secure ✗).
      25는 Workers 에서 아예 막혀 있다
- [ ] 수신/발신 주소 칸: 비웠을 때 실제로 쓰일 폴백 값을 placeholder 로 표시
- [ ] **테스트 발송 버튼**: 저장 후 누르게 안내하고, 실패 시 서버가 준 `detail` 을
      그대로 보여준다
- [ ] 저장은 `mail` 키만 보낸다 (부분 업데이트)

## 6. 환경변수 정리

| 변수 | 용도 | 필수 여부 |
|---|---|---|
| `RESEND_API_KEY` | provider 미설정/resend 이고 저장된 키가 없을 때의 폴백 | 설정 화면으로 키를 넣었다면 불필요 |
| `MAIL_FROM` (이 프로젝트에선 `INQUIRY_FROM_EMAIL`) | 발신 주소 폴백 | from 을 설정에 넣었다면 불필요 |

발신 주소는 어느 경로든 **도메인 인증(SPF/DKIM)이 된 주소**여야 한다 — Resend 는
인증 안 된 from 을 거절하고, SMTP 는 보내지긴 해도 스팸함으로 간다.
